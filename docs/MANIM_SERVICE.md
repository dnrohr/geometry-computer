# Local video rendering service

The application integrates with ManimGL through a deliberately narrow local boundary. Browsers cannot launch Python or choose arbitrary filesystem paths. A separate service listens only on `127.0.0.1`, validates version 2 render documents, selects output paths under `media/service`, and launches the pinned project renderer.

## Start the service

After completing the Manim environment setup:

```powershell
npm run manim:service
```

Keep that terminal open while using the application. The SVG interface and JSON/SVG exports continue to work normally when the service is stopped.

## Application workflow

The “Render an MP4” panel offers draft, standard, and high quality. Origami documents also offer flat or 3D hinge folding. The panel reports these phases:

1. Construction compiled in the browser.
2. Document validation.
3. Waiting for serialized renderer access.
4. Scene preparation.
5. Frame rendering and video encoding.
6. Complete, failed, or cancelled.

On completion, the panel shows the exact local path and a browser download. Cancellation terminates the renderer and removes its temporary document and partial video.

## Trust boundary

- The service binds to `127.0.0.1`, never all network interfaces.
- Browser requests are accepted only from `localhost` or `127.0.0.1` origins.
- Request bodies are limited to 5 MB.
- Documents pass the Python v2 validator before process launch.
- Quality and fold mode use fixed allowlists.
- Filenames and output directories are generated by the service.
- Manim jobs are serialized to avoid competing OpenGL contexts.
- Completed MP4s are streamed through a job-scoped download endpoint.
- Failed and cancelled jobs never expose an output path.

The service does not provide a generic shell, arbitrary arguments, arbitrary source files, or arbitrary output destinations.

## API summary

- `GET /health`
- `POST /jobs`
- `GET /jobs/{id}`
- `DELETE /jobs/{id}`
- `GET /jobs/{id}/video` after completion

This API is intended only for the local Geometry Computer UI, not remote deployment.
